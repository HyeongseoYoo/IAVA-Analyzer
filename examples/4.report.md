# Codex Bug Report

Bug #1: right out-of-bounds write at line 18

1. Main reason

`CurrentUser` can be changed by interrupt `handler 0` after interrupts are enabled. The main code then uses `CurrentUser` as an index into `Status`, which only has 4 elements. If the interrupt sets `CurrentUser` to `INVALID`, the write becomes `*Status[100] := 1`, which is outside the valid range `0..3`.

2. Trace

- Line 9: `Status := malloc(4, 0)`
  - Allocates an array with valid indexes `0, 1, 2, 3`.

- Line 8: `CurrentUser := INIT`
  - Initializes `CurrentUser` to `0`.

- Line 2: `INIT := 0`
  - Confirms the initial value is safe.

- Line 14: `enable`
  - Interrupts can now run.

- Handler 0, line 11: `CurrentUser := INVALID`
  - `handler 0` may run and overwrite `CurrentUser`.

- Line 6: `INVALID := 100`
  - So `CurrentUser` may become `100`.

- Line 18: `*Status[CurrentUser] := 1`
  - The program writes to `Status[CurrentUser]`.
  - If `CurrentUser == 100`, this is `Status[100]`, beyond the allocated size of 4.

3. Interrupt involved

`handler 0` is part of the cause. It assigns `INVALID` to `CurrentUser`.

4. Concrete fix

Do not let `CurrentUser` change between the validity check and the array write. For example:

```si
main {
  enable;
  disable;
  if CurrentUser = INVALID
  then CurrentUser := INIT
  else *Status[CurrentUser] := 1
  enable;
}
```

Alternatively, copy `CurrentUser` into a local variable while interrupts are disabled, validate that copy, and use only the validated copy for indexing. The key requirement is that the value checked must be the same value used as the array index.
